01 / Decision

Build a verifiable ledger, not a larger logger.

The best architecture is a privacy-minimal, typed event service with atomic hash-chained appends, signed recorder receipts, growing Merkle checkpoints, independent observation, an encrypted evidence vault, and a pure historical verifier.

Recommended architecture

Keep detached proofs stable. Give each ledger epoch exactly one authoritative recorder inside a new @kya-os/mcp/audit domain.

Checkpoint is either the managed recorder or a verified mirror of a self-hosted recorder—never both. xmcp-i supplies ordered platform adapters; mutable dashboard rows and edge KV never assign authoritative sequence.

01 / Origin

Detached proof

The actor or server signed the request, response, decision, audience, and authorization claims.

02 / Recorder

Append receipt

The epoch's sole authority accepted this exact event at a declared ledger sequence and head.

03 / Observer

Observed checkpoint

An independent party retains and compares signed heads; authenticated gossip makes conflicting observed views detectable.

02 / Baseline state

An excellent foundation with one formerly overclaimed layer.

This is the pre-implementation baseline that motivated the design. The delivered audit domain replaces the lossy abstraction while retaining the repo's provider architecture, JCS content binding, strict verification, two-line adoption, and TDD posture.

A- / FOUNDATION

Clean ports & composition

Crypto, clock, fetch, session, grants, identity, and storage are injected through small interfaces. The audit service can follow the same pattern.

A- / PROOFS

Strong content binding

JCS + SHA-256 binds request and response content; card proofs demonstrate the right opaque-signer and strict-verifier shape.

D+ / RETENTION

One call per session

The memory provider intentionally suppresses every audit record after the first call in a session, preventing a reconstructable call sequence.

D+ / COMPLETENESS

Success-only, silent loss

Errors, denials, challenges, replay rejection, and delegation lifecycle are absent; sink failures are swallowed.

PROOF REPLAY

Session nonce is reused

Two distinct proofs in one session empirically shared a nonce. The first verified; the second failed as replay. Per-call proof identity is required.

SCHEMA DRIFT

Seconds, milliseconds, and roles

The live audit schema and package disagree on time units, absent response hashes, supported DID forms, and whether did is caller or server.

UI SEMANTICS

Presence can look verified

Checkpoint can map a nonempty attestation hash to “Verified” or “Signed & replayable” without chain, checkpoint, key-policy, or evidence checks.

Critical distinction: a signature can authenticate an individual record. It cannot prove that records were not omitted, reordered, deleted, or presented in a different fork.
03 / Value

From “trust our logs” to “verify our evidence.”

The protocol's differentiated value is not more telemetry. It is portable evidence that lets customers, auditors, incident responders, and the Checkpoint UI independently evaluate what is known—and what remains indeterminate.

04 / Target system

Six responsibilities. Narrow ports. One source of truth.

The producer service freezes semantics; the epoch's recorder alone assigns order and signs. Providers own platform mechanics, while Checkpoint's product views stay rebuildable. The separation remains SOLID in local and managed deployments.

01 / EVENT

Typed semantic catalog

Session, tool, proof, authorization, consent, delegation, policy, key, checkpoint, retention, and access events—including every negative path.

02 / JOURNAL

Conditional append

Unique ledger/sequence and ledger/event ID constraints. Identical retry returns its original receipt; conflicting reuse is a hard error.

03 / EVIDENCE

Privacy separation

Keyed/pseudonymous metadata in retained ledger segments; exact proof and collateral use opaque vault IDs, encryption, and separate retention.

04 / CHECKPOINT

Merkle transparency

Efficient inclusion and consistency proofs over sequence-ordered entry digests, with signed head and previous checkpoint link.

05 / VERIFY

Historical truth dimensions

A signed inventory commits bundle scope; chain, checkpoint, observer, anchor, evidence, proof, and policy are independent verdicts.

06 / PROJECT

Rebuildable product views

Checkpoint's activity, proof, gateway, session, and reputation experiences remain fast projections—never the evidence authority.

06 / Protocol contract

Make correctness expressible in the interface.

A generic key/value store cannot promise atomic order. The new provider must expose compare-and-append, idempotency, immutable range reads, and declared durability.

The store persists; the service decides.

AuditTrailService freezes the producer core and submits it through AuditRecorderClient. Only AuditRecorderService assigns epoch/time/sequence, signs, and uses the journal CAS. The journal persists exact supplied bytes and never invents protocol behavior.

07 / Failure semantics

Availability is a policy, not a catch block.

Regulated deployments need to know whether an acknowledgement means “attempted,” “durably queued,” or “committed to the ordered ledger.” The selected mode must be visible in capabilities and receipts.

sequenceDiagram participant M as MCP adapter participant A as Audit service participant J as Ordered journal participant T as Tool / external system M->>A: tool.call.started (stable idempotency key) A->>J: compare-and-append expected head J-->>A: signed append receipt A-->>M: intent durable M->>T: execute side effect T-->>M: result / error M->>A: completed or failed A->>J: compare-and-append alt terminal append succeeds J-->>A: receipt A-->>M: terminal receipt else terminal append fails after side effect A-->>M: degraded + dangling intent A->>J: reconcile via outbox end
Hard limit: middleware cannot atomically commit an arbitrary external side effect and an audit record. Use a transactional outbox when the host shares the datastore; otherwise use intent/completion events, idempotency, reconciliation, and authenticated source-sequence/high-water heartbeats. The ledger proves accepted history—not events dropped before submission.
08 / Cross-repo fit

Protocol core in MCP. Adapters in xmcp-i. Product evidence in Checkpoint.

This division follows the codebases' existing strengths and prevents the dashboard's mutable tables or edge KV from becoming an accidental cryptographic authority.

@KYA-OS/MCP

Canonical contract

Audit types, strict schemas, digest suites, service, verifier, Merkle logic, memory reference, conformance vectors, legacy bridge, and MCP instrumentation.

XMCP-I

Platform adapters

PostgreSQL/Node journal, Cloudflare Durable Object journal, R2 evidence, durable delivery/outbox, anchor providers, and shared contract tests.

CHECKPOINT

Authority or verified mirror

Deploy as the managed AuditRecorderService, or ingest exact self-hosted envelopes without resequencing. Then project integrity state, reconciliation, and policy-authorized signed bundles.

MIGRATION BOUNDARY

Commit the old world; do not rewrite it.

Create a signed legacy import manifest containing source range, row count, aggregate commitment, importer, and migration time. Start the new chain at a declared genesis/import boundary. Preserve existing activity/session/proof tables as projections and label pre-boundary rows unverified_legacy.

Dependency gate: align direct and transitive KYA package versions across Checkpoint, contracts, runtime, and Cloudflare before enabling the new envelope.
09 / Assurance

Make the promise machine-readable.

Audit assurance must be independent from identity/conformance level. A sophisticated identity deployment with a no-op logger must never look equivalent to a witnessed transparency ledger.

AAP-0NoneNo audit

No audit service and no implied assurance.

AAP-1RecordedStructured

Typed capture, declared sink and retention, observable failure. No continuity claim.

AAP-2ChainedTamper-evident

Durable atomic append, sequence/previous digest, signed receipt, and pure verifier.

AAP-3TransparentMerkle proof

Growing tree, signed checkpoints, inclusion/consistency proofs, health monitor and reconciliation.

AAP-4ObservedExternal observation

An independent party retains checkpoints and uses authenticated comparison/gossip plus freshness monitoring. WORM, RFC 3161, and SCITT receipts add durability or time evidence; alone they do not detect a split view.

PRIVACY

Integrity retention ≠ evidence retention

Use pairwise/keyed references in the ledger and encrypted artifacts in the vault. Sealed segment transitions, TTL, legal hold, disposal, and crypto-shredding are explicit; no convergent encryption.

COMPLIANCE

Evidence-enabling, never self-certifying

EU AI Act, GDPR, NIST AU controls, and OWASP logging guidance inform coverage and controls. Classification, configuration, human procedure, and applicable law remain deployment responsibilities.

10 / Rollout

Additive, test-gated, and reversible.

Every phase can ship behind configuration without deleting committed evidence or breaking the mature proof wire format. The sequence prioritizes replay correctness before a new auditability claim.

0

Correctness

Per-call nonce, historical verifier, KID binding, safe canonicalization, delegation evidence.

1

Contract

Schemas, vectors, service, memory reference, provider kit, legacy bridge.

2

Coverage

All outcomes and lifecycle seams; shadow emission and parity reports.

3

Durability

Postgres, Durable Object, encrypted evidence, outbox, failure injection.

4

Product

Checkpoint managed recorder or verified mirror, projections, chain health, signed bundles.

5

Transparency

Merkle proofs, signed checkpoints, independent monitors/gossip, supporting receipts.

CONCURRENCY GATE

100+ writers, no fork

Contiguous per-epoch sequence under contention, crash/restart, stale head, timeout, duplicate delivery, transition, and multi-instance tests.

EVIDENCE GATE

Offline reproducibility

Policy-authorized exporter, signed scope/inventory manifest, cross-language vectors, and byte-for-byte bundles with explicit verdicts.

PRIVACY GATE

Deletion without corruption

Tenant isolation, secret-negative tests, legal hold, TTL, redaction, disposal, access audit, and crypto-shredding.

Grade rationale

A / 9.6 delivered. Production A+ remains deployment-earned.

The reference implementation now includes ordered replay, scalable proofs, adapter portability, privacy-aware retention, independent observation, and developer ergonomics, with executable concurrency, failure, mutation, and cross-language gates. A production A+ claim additionally depends on contract-conformant durable adapters, independent administration, retention operations, and incident exercises.
